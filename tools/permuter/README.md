# `tools/permuter/` — driving decomp-permuter with MWCC-MIPS

A search harness for the *one-instruction-off* functions that shape templates can't crack.
`decomp-permuter` mutates a C candidate at the AST level, recompiles it, and scores the disassembly
against a target, keeping improvements.

Two projects are here, both built and verified: `FUN_00130060/` (the `sltu` guard family) and
`FUN_00334460/` (the still-open 76-byte variant, [`../../docs/engine/guard-family.md`](../../docs/engine/guard-family.md) §5).
`run.sh` starts, compiles through `compile.sh`, scores against `target.o`, and iterates at ~800/s.
A 150 s run (~118k iterations) did not find a match; the tool is built for hours, not minutes.

## What it is and is not good for

The permuter is the right instrument for "one instruction off", and it runs fine on this target —
but on the guard family **it did not find the answer and could not have**: the base source had no
`bool` at all, so the named-boolean value conversion that fixes the family was outside its mutation
space. Both harnesses ended at the base score of 105 (66k and ~1.2 M iterations respectively), and the
idiom was found by reading the code instead (finding [#312](../../docs/findings/findings-0251-0500.md#f312)). The measured cost/benefit of scaling it
is in [`../../docs/engine/m2c-bulk.md`](../../docs/engine/m2c-bulk.md) §Measured negatives — the
near-miss tier it would work on is less than 1 % of the remaining code bytes.

## Setup

Two things must be supplied locally, both under `local/` (gitignored — see
[`../../README.md`](../../README.md) §Prerequisites):

```sh
# the permuter source, and its only dependency
python3 -m venv local/permuter-venv
local/permuter-venv/bin/pip install --quiet toml
```

A system-wide `pip install` is blocked by PEP 668 anyway, so the harness uses its own venv. The
harness itself is committed here; `target.o` is generated by `build_target.sh` and is never
committed, because it is a copy of game code.

## Running it

```sh
tools/permuter/FUN_00130060/run.sh                 # regenerate target.o, then search
tools/permuter/FUN_00130060/run.sh --better-only   # print each improvement, avoid stdin
tools/permuter/FUN_00130060/run.sh --stop-on-zero  # stop on an exact match
```

It runs until interrupted. Progress is `iteration N, E errors, score = S`, where **lower is better
and 105 is the base score** for the current `base.c` (the higher numbers are failed mutations). A win
prints the improved candidate and writes it to the project directory.

**`--print-diffs` reads stdin.** It calls `input("Press any key to continue...")` after each
improvement, so `run.sh --print-diffs > log 2>&1 &` dies immediately with `EOFError`. Use
`--better-only`, which writes `output-<score>-N/` and prints the improvement line, or feed stdin.

## The compile contract

The permuter preprocesses the candidate in C mode and then hands the *preprocessed* text to
`compile.sh` — so `#ifdef __cplusplus` is already resolved and any `extern "C"` is stripped. For the
`bool` idiom that matters: the `typedef _Bool bool;` line pycparser needs would reach MWCC's C++
front end, which rejects `_Bool`, so `FUN_00334460/compile.sh` deletes that line
(`sed '/^typedef .* bool;$/d'`) before compiling. No MWCC-MIPS code adapter was needed:
`compiler_type` in `permuter_settings.toml` only selects randomization weights, and the build
command comes from `compile.sh`. Arch detection reads `e_machine` from `target.o` (`8` = MIPS) and
picks `mips-linux-gnu-objdump`.

A project directory must contain exactly **`base.c`, `target.o`, `compile.sh`**.

## The four traps, all hit while building this

1. **The candidate must be named `base.c`** (the permuter checks that exact filename), but **MWCC
   only has a `bool` type in C++ mode**, and it picks the language from the file *extension*.
   `compile.sh` copies to a `.cpp` before invoking the compiler.
2. **C++ mangles names**, so `extern "C"` is needed for the linked symbol to stay
   `FUN_00130060` — but the permuter's own parser is C-only and errors on `extern "C"`. `base.c`
   guards it with `#ifdef __cplusplus`: plain C to the permuter, C++ linkage to MWCC.
3. **GNU `as` pads every section to 16 bytes**, so a 72-byte function lands in an 80-byte `.text`,
   and the permuter disassembles the *whole object* (no symbol filter) — the padding would make a
   perfect score unreachable. `build_target.sh` rewrites `sh_size` to 72 (safe: all relocations sit
   below 72).
4. **MIPS `as` needs `$`-prefixed registers** (bare `sp`/`ra` parse as symbols, giving
   `invalid operands` on every line) **and `.set noreorder`** (otherwise it inserts filler nops for
   load hazards and the target comes out 96 bytes instead of 72).

## Making `target.o` compare equal to a correct compile

The permuter compares *disassembly text* and normalises MIPS relocations by symbol name
(`src/objdump.py: process_mips_reloc`). So the target must render the same way the compiler's output
does. `build_target.sh` therefore transcribes the retail function symbolically (`%hi`/`%lo` against
`DAT_0055ebc0`, `jal FUN_001301c0`) and leaves `DAT_0055ebc0` **undefined** so `as` emits
`R_MIPS_HI16`/`R_MIPS_LO16` against the symbol. Pinning it to a constant instead resolves the pair at
assembly time, and the target then shows `lui at,0x56` where the candidate shows a relocation.
