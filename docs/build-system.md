# Build system

GNU make drives the build. decomp-toolkit only splits PowerPC DOL/REL files, so this MIPS ELF uses
the repository's own tools, in a layout close to [dtk-template](https://github.com/encounter/dtk-template).

| Path | Holds |
| --- | --- |
| `config/<GAMEID>/config.yml` | executable, image geometry and the version's tables, read by [`tools/project.py`](../tools/project.py) |
| `config/<GAMEID>/symbols.txt` | `va size name`, generated by `tools/split.py` |
| `config/<GAMEID>/units.tsv` | translation units and their build profiles ([build profiles](engine/build-profiles.md)) |
| `config/<GAMEID>/regions.tsv` | what each part of the image is, tested against retail by `tools/check_regions.py` ([module map](engine/module-map.md)) |
| `config/<GAMEID>/build.sha1` | SHA-1 of the merged load image the relink must reproduce |
| `orig/<GAMEID>/` (gitignored) | the private retail executable, e.g. `orig/SLUS-20836/SLUS_208.36` |
| `objdiff.json` | generated by `make objdiff`; one unit per function (target-only for code without source) |

The version is `SLUS-20836` (USA). Its address-bearing tables live in `config/SLUS-20836/`;
project-wide policy files stay in `config/` (`debt-baseline.json`, `typed-coverage.json`,
`typed-scope*`).

## Commands

```sh
make check                                 # every unit verified byte-for-byte (tools/check.py)
make link                                  # relink, linkcheck, then build/<GAMEID>/main.bin against build.sha1
make objdiff                               # objdiff.json and the base and target objects; open the folder in objdiff
make progress                              # the progress numbers (tools/progress.py)
```

`make iso` (with `DISC=<path>` when the disc is not in `orig/<GAMEID>/`) is a publishing step, outside
the build and CI: it relinks, then writes the executable into a copy of your disc at
`build/<GAMEID>/<GAMEID>.iso` with `tools/make_iso.py`. The copy is game data and stays in `build/`.

## objdiff objects

The base object of a unit is the function's definition compiled under its unit profile, extracted
from its source file exactly as `tools/check.py` does (a registered emitted member builds its
owner). The target object holds the function's retail instructions, produced by [`tools/target_asm.py`](../tools/target_asm.py): `asm/<name>.s`
keeps every retail word as a plain `.word`, which would show each call and address pair as a
difference against the compiled object's relocations, so the target assembly emits those words
with the relocated field cleared behind a `.reloc` directive naming the same symbol the compiler
references. After relocation the target bytes are the retail bytes exactly. A unit is marked
`complete` when its function is `match` in `data/check-categories.tsv`; objdiff's
percentage is a diff measure, the matching oracle remains `tools/check.py` and `tools/linkcheck.py`.

## Private inputs

`orig/` holds one folder per version with a `.gitkeep`; everything else in it is ignored. Link or
copy the retail executable there (for example `ln -s ../../roms/dw4/game.elf orig/SLUS-20836/SLUS_208.36`);
the CI oracle creates the same link from its runner environment. `config.yml` records the
executable's SHA-1 so a wrong file is caught before any comparison.

`asm/`, the per-function split of the retail code, is the other private input, and a generated
one: `make check` runs `tools/split.py --ensure`, which writes it from the
executable when it is missing or stale. It is gitignored.
