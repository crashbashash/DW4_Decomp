# Build system: the dtk-template layout for a PS2 ELF

The repository follows the layout of [dtk-template](https://github.com/encounter/dtk-template),
the scaffold most GameCube/Wii decompilations use, so a reader who knows those projects finds
the same pieces in the same places. decomp-toolkit itself only splits PowerPC DOL/REL files;
for this MIPS ELF the same layout drives the repository's own tools.

| dtk-template | Here |
| --- | --- |
| `configure.py` → `build.ninja` | `configure.py` → `build.ninja` (generator: [`tools/project.py`](../tools/project.py)) |
| `config/<GAMEID>/config.yml` | `config/<GAMEID>/config.yml`: executable, image geometry and the version's tables |
| `config/<GAMEID>/symbols.txt` | `config/<GAMEID>/symbols.txt` (`va size name`, generated by `tools/split.py`) |
| `config/<GAMEID>/splits.txt` | `config/<GAMEID>/units.tsv`: translation units and their build profiles ([build profiles](engine/build-profiles.md)) |
| `config/<GAMEID>/build.sha1` | `config/<GAMEID>/build.sha1`: SHA-1 of the merged load image the relink must reproduce |
| `orig/<GAMEID>/` (gitignored) | `orig/<GAMEID>/<boot file>`: the private retail executable, e.g. `orig/SLUS-20836/SLUS_208.36` |
| `objdiff.json` | generated by `configure.py`; one unit per function (target-only for code without source) |
| progress for decomp.dev | `ninja report` → `build/<GAMEID>/report.json` (`objdiff-cli report generate`) |

The version is `SLUS-20836` (USA). Its address-bearing tables live in `config/SLUS-20836/`;
project-wide policy files stay in `config/` (`debt-baseline.json`, `typed-coverage.json`,
`typed-scope*`).

## Commands

```sh
python3 configure.py                       # writes build.ninja and objdiff.json
ninja                                      # relink, linkcheck, then build/<GAMEID>/main.bin against build.sha1
ninja check                                # every unit verified byte-for-byte (tools/check.py)
ninja objdiff                              # the objdiff base and target objects; open the folder in objdiff
ninja report                               # build/<GAMEID>/report.json for decomp.dev
python3 configure.py progress              # the progress numbers (tools/progress.py)
```

`make check`, `make link`, `make typed-check` and the other Make targets run the same tools and
stay the commands the git hooks, the CI oracle and `CLAUDE.md` use.

`make iso` (with `DISC=<path>` when the disc is not in `orig/<GAMEID>/`) is a publishing step, outside
the build and CI: it relinks, then writes the executable into a copy of your disc at
`build/<GAMEID>/<GAMEID>.iso` with `tools/make_iso.py`. The copy is game data and stays in `build/`.

## objdiff objects

The base object of a unit is the function's definition compiled under its unit profile, extracted
from its source file exactly as `tools/check.py` does (a registered emitted member builds its
owner). The target object holds the function's retail instructions, produced by [`tools/target_asm.py`](../tools/target_asm.py): `asm/<name>.s`
keeps every retail word as a plain `.word`, which would show each call and address pair as a
difference against the compiled object's relocations, so the target assembly emits those words
with the relocated field cleared behind a `.reloc` directive naming the same symbol the compiler
references. After relocation the target bytes are the retail bytes exactly. A unit is marked
`complete` when its function is `match` in `data/check-categories.tsv`; objdiff's
percentage is a diff measure, the matching oracle remains `tools/check.py` and `tools/linkcheck.py`.

## Private inputs

`orig/` holds one folder per version with a `.gitkeep`; everything else in it is ignored. Link or
copy the retail executable there (for example `ln -s ../../roms/dw4/game.elf orig/SLUS-20836/SLUS_208.36`);
the CI oracle creates the same link from its runner environment. `config.yml` records the
executable's SHA-1 so a wrong file is caught before any comparison.

`asm/`, the per-function split of the retail code, is the other private input, and a generated
one: `configure.py` and `make check` run `tools/split.py --ensure`, which writes it from the
executable when it is missing or stale. It is gitignored; the template keeps its generated
assembly under `build/` for the same reason.
