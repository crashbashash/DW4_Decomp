# Build system

GNU make drives the build. decomp-toolkit only splits PowerPC DOL/REL files, so this MIPS ELF uses
the repository's own tools, in a layout close to [dtk-template](https://github.com/encounter/dtk-template).

| Path | Holds |
| --- | --- |
| `config/<GAMEID>/config.yml` | executable, image geometry and the version's tables, read by [`tools/project.py`](../tools/project.py) |
| `config/<GAMEID>/symbols.txt` | `va size name [display]`, generated by `tools/split.py`; the display column holds the original name where it differs, and for a member the source defines the demangled `Gap::<Lib>::<Class>::<method>` of its `config/<GAMEID>/compiler-names.tsv` row (the key stays `<Class>_<Method>`) |
| `config/class-members.tsv`, `config/typed-fields.tsv`, `config/converted-classes.tsv` | the C++ members, typed reference fields and `Gap::` polymorphic classes `scripts/gen_type_headers.py` writes into `include/dw4/support/reflected.h` ([typed coverage](engine/typed-coverage.md#c-members-typed-references-and-converted-classes)) |
| `tools/gen_odl_source.py` | a library's reflection boilerplate in igen's form, with a retail comparison ([generated boilerplate](engine/reflection-registration.md#generated-boilerplate)) |
| `config/<GAMEID>/units.tsv` | translation units and their build profiles ([build profiles](engine/build-profiles.md)) |
| `config/<GAMEID>/compiler-names.tsv` | the C++ compiler name of each member a unit row places, with its retail address and retail name; generated from `unit-objects.json` by `tools/compiler_names.py` ([the compiler-name map](engine/emitted-functions.md#the-compiler-name-map)) |
| `config/<GAMEID>/regions.tsv` | what each part of the image is, tested against retail by `tools/check_regions.py` ([module map](engine/module-map.md)) |
| `config/<GAMEID>/build.sha1` | SHA-1 of the merged load image the relink must reproduce |
| `orig/<GAMEID>/` (gitignored) | the private retail executable, e.g. `orig/SLUS-20836/SLUS_208.36` |
| `objdiff.json` | generated by `make objdiff`; one unit per function (target-only for code without source) |

The version is `SLUS-20836` (USA). Its address-bearing tables live in `config/SLUS-20836/`;
project-wide policy files stay in `config/` (`debt-baseline.json`, `typed-coverage.json`,
`typed-scope*`).

## Commands

```sh
make check                                 # every unit verified byte-for-byte (tools/check.py)
make link                                  # relink, linkcheck, then build/<GAMEID>/main.bin against build.sha1
make objdiff                               # objdiff.json and the base and target objects; open the folder in objdiff
make progress                              # the progress numbers (tools/progress.py)
```

`make iso` (with `DISC=<path>` when the disc is not in `orig/<GAMEID>/`) is a publishing step, outside
the build and CI: it relinks, then writes the executable into a copy of your disc at
`build/<GAMEID>/<GAMEID>.iso` with `tools/make_iso.py`. The copy is game data and stays in `build/`.

## Member conversion

`tools/memberize.py <table>` rewrites free `<Class>_<Method>` functions and `g_<Class>_…` data as members of their
class (dry run by default, `--diff` to see it, `--apply` to write). Each table row is `<C name>\t<member>`: the
member as `Class::name`, declared in `config/class-members.tsv` (object macros expanded), or as a full signature
(`static CallbackArray *igRenderer::arkRegisterInternal()`), whose declaration it adds to that table; a class's
`operator new`/`operator delete` (`void *igObject::operator new(size_t cSize, size_t allocSize, igMemoryPoolView
*mp)`) is a static member like any other (`__nw__Q33Gap4Core8igObjectFUiUiP16igMemoryPoolView`, called
`Gap::Core::igObject::operator new(a, b, c)` outside the class, bare inside it). It rewrites
the definition head, the receiver as `this` without a local copy of it (`self->x` becomes `x`, a dispatch view's
virtual `((View *)this)->f()`), a member the class defines inline loses its C copy, and the C++ callers
(`obj->m(a)`, `Class::m`, bare inside the class's members). Comments keep the C name, which stays the symbol's
retail name in `symbols.txt` (rewriting it gave prose such as "kept local: Gap::Core::igObjectList::setCount has no
home"); only a code span holding just the C name (`` `igObjectList_SetCount` ``) names the member as code now does
(`igObjectList::setCount`). In `unit-objects.json` the placing
unit's key becomes the compiler name, which `tools/compiler_names.py --write` then binds; it prints the
`tools/whole_file_rows.py --unit-va <va> --cxx --write` runs that regenerate the touched units' rows. A body
spelled for its bytes in igen's form (tables as function-local statics, a cast a function pointer's new type
needs) is written by hand afterwards; the tool notes the casts. The root design, the boundary rules and the
conversion order are in [member conversion](engine/member-conversion.md).

- **Spelling.** A converted class (`config/converted-classes.tsv`) is `Gap::<Library>::Class`, and its
  out-of-line definitions are written as the kit's `.cpp` files and igen's ODLSource write them: inside
  `namespace Gap { namespace <Library> {`, the head naming the class alone (`void igRenderer::draw()`), one block
  per run of adjacent members (a free function between them stays outside). `tools/gen_odl_source.py` writes its
  fragments the same way; both take the block from `tools/cxxscope.py`. `memberize.py --respell` puts every
  remaining `T Gap::<Library>::Class::m(...)` definition of the tree into that form, joining a block it writes to a
  block of the library right before or after it; memberize and classconv likewise join the two blocks a removal of
  theirs left side by side (a C definition, an igen file table). The blocks a file already has elsewhere keep
  their bounds and the blank lines between definitions stay, so a second `--respell` changes nothing.
  `tools/units.py` reads a namespace block as transparent, as it reads `extern "C" { }`, so every tool still finds
  the definitions.
- **Flat and Gap types.** The flat struct of a converted class and its Gap class are two types of one name. A
  receiver or `Class *` argument declared as the flat struct (or a flat subclass, or not declared) is cast to the
  Gap class (`((Gap::Core::igObject *)m)->realloc(…)`; bare `igObject` in Gap's scope), a cast of `this` to the
  flat struct passed as a Gap parameter goes, and a body moving into the class keeps its types' meaning: its bare
  receiver passed on is `(::igObject *)this`, every other bare `igObject` in it `::igObject`.
- **Constructors.** `Class_Init(T *self, …)`-style C constructors become `Class::Class(…)` (declared in
  `class-members.tsv`): no return type, and the statements MWCC writes itself go — the vtable store into the
  receiver, `return self;`, and a first-statement call of a base class's constructor (this batch's or one the
  compiler-name map binds), which becomes implicit or, with arguments, the initialiser ` : Base(args)`. A base
  constructed after other statements is refused.
- **Destructors.** Alchemy's destructors are implicit and not virtual: `Class::~Class` for a class that declares
  none removes the C body `Class_Destroy(self, flag)` (the compiler writes the vtable stamp, the members'
  release and the delete where an object is destroyed). `Class_Destroy(p, 1)` on a pointer declared as the Gap
  class becomes `delete p`. A declared out-of-line destructor is refused (its user body is written by hand).
- **The boundary.** Code that still names a converted member's C name keeps it: C callers, an unconverted
  subclass's direct call of a virtual default, a construction or destruction of an object still written as a
  flat struct (a GetVTable probe), and a call of a private member from outside its class (a protected one from
  outside the class and its subclasses), which the kit reaches only through the class's own inlines
  (`igObject::release()` for `internalRelease`). While such a user exists the prototype stays in the home header
  (under `include/`, named for the class first), and in another header only for a user's unit that does not read
  the home header; every other declaration goes, and all of them once no code names the C name. A `static
  inline` C++ overload of the C name that forwarded another pointer type to it goes when no C++ code names the C
  name any more. `memberize.py --check` reports each declaration of a converted member's C name (a retail name
  of `compiler-names.tsv` for a converted class's member) that rule would remove, and exits 1 when there is one.
- **Macros and class bodies.** A call in a `#define`'s replacement text (continuation lines included) is
  rewritten like any call, its receiver cast to the class (a macro parameter parenthesised), and so is a call in
  a member function a class body defines; a statement is a declaration of the C name only when a type precedes
  it. A parameter spelled `Gap::<Library>::Class *` in a C form compares equal to the member's bare `Class *`
  and is written bare in the class's scope. Rows a batch adds to `class-members.tsv` go after their class's
  last row.
- **A reused receiver.** A C body that assigns its receiver once done with it (`self = (igRegistry *)r.p;`)
  keeps the name as a local of the receiver's declared type from that statement on: the assignment declares it
  when every later use is inside its block, else the body's first line does. An assignment inside an expression,
  or inside a loop that read the receiver before it, is refused. An argument `&x` for a reference parameter
  `T &`, where `x` is declared as `T`, is `x`.
- **Arguments.** A call's arguments take the member's order where the C prototype orders them otherwise
  (igRegistry_GetValueFloat's `create, defaultValue` for the kit's `defaultVal, createValue`), mapped by type and
  name; the C order stands while it fits and no other order matches more names, and an order the types and names
  leave open is refused. An integer passed for an enum parameter is cast (`(IG_GFX_DRAW)primitive`,
  `(Gap::Core::igFile::OpenMode)n` outside the class), the address of a temporary the C form took a pointer to
  is the temporary (`&igStringRef(name)` becomes `igStringRef(name)`, built in place as before), and for a
  reference to a typedef'd class (`igStringObjRef &`) a name declared as it, or its address (`&x`,
  `(igStringObj **)&x`, `&x.p`), is the name, any other pointer dereferenced (`*(igStringObjRef *)&text`).
- **Compiler names.** A member's parameter types are spelled as its class's scope finds them: a type nested in
  the class or a base by its owner (`Q43Gap4Core6igFile8OpenMode`), a function or function-pointer typedef as
  its type (`igIOCallbackFunction *` is `PFii_v`), a converted class as its Gap class. A key of a converted
  member whose parameter names a class converted since as the flat struct
  (`platformLoad__Q33Gap3Gfx7igImageFP6igFile` once igFile is converted) is renamed by every memberize batch and
  by `memberize.py --rekey --apply` (after a merge), which print the `whole_file_rows.py` runs of the rows it
  touched; `memberize.py --check` reports one. A template instance naming a converted class as its flat struct
  (`__dt__32igSmartPointer<14igVertexStream>Fv`, `getElementMeta__…igTObjectList<…>CFv`) names the instance where
  the source spells it: code in the Gap namespaces (the converted members) now instantiates it with the Gap class,
  while code at file scope still holds the flat struct's (`__dt__25igSmartPointer<8igObject>Fv` stays in many
  units). A name can also outlive its class: a view retired (`__dt__33igSmartPointer<15igSemaphoreView>Fv`) or a
  helper renamed (`__dt__10ScopedLockFv` once it is the kit's igScopeLock). So `--rekey` compiles each whole-file
  unit holding such a name (a template argument a converted class's flat struct, or a class no source declares;
  tools/project.py `compile_unit`, as check.py builds it) and renames a name its object no longer has to the one
  object name that differs from it only in Gap scopes (`__dt__42igSmartPointer<Q33Gap3Gfx14igVertexStream>Fv`, the
  lengths recomputed), else to the one object name the row does not list that differs from it only in the classes
  it names (`__dt__11igScopeLockFv`), in every field of the row, `stripped` too; a `stripped` name with neither
  goes (the object no longer compiles that body). A memberize batch prints it as a step once the bodies compile,
  before the `whole_file_rows.py` runs, and `tools/classconv.py`'s last step runs it. `--check` compiles nothing
  and does not report these.
- **Rows.** `tools/whole_file_rows.py --unit-va <va> --cxx --write` regenerates a unit's row from its present
  row: the addresses, strips, static-initializer entry and data names it settled stay settled, the retail
  functions it left to link from retail (a partial file) stay so without `--partial`, a name it left out
  that binds without a row stays out, and a `data`/`externals` entry or `anon` address it listed stays in its
  place while its name still binds at that address (the object, symbols.txt, data-names.tsv, the compiler-name
  map, another unit's row or the address in the name). A member whose mangled name changed only in a parameter's
  type (`platformLoad__Q33Gap3Gfx7igImageFP6igFile` once igFile is the Gap class) or in its class template's
  argument (`__dt__32igSmartPointer<14igVertexStream>Fv` once igVertexStream is) takes its former name's address
  when it fits there and one name of that class, method, constness and parameter count went and one came.
  Byte-identical functions left with the same starts (two empty virtual slots, inline destructors of one shape) take
  the starts retail names them at: the calls, pointers and vtable words of the members placed so far, read as for
  `duplicates`; one retail names outside the range is no member. What retail leaves open stops the run naming each
  candidate and its starts, for `--at name=va`. Regenerating an unchanged unit, or a caller whose code changed only
  at call sites, writes its row unchanged, so a conversion's row diff is what the conversion changed. The rows are
  written only once the file loads and the compiler-name map builds from it; otherwise the run stops naming why
  and leaves the file as it was.
- **Typed coverage.** `tools/typed_coverage.py` counts a member's accesses as it counts a free function's
  (`this->x`, a bare field, a read through a typed member such as `_visualContext->x`, a constructor's body),
  a read through a reference (`other._refCount`) as one through a pointer, a converted class's constructor's vtable
  store, and the accesses the compiled code makes through what the headers define inline: an inline member called on
  an object of known class (`_Meta->isValid()`), a smart-pointer member's assignment, and a converted class's
  implicit destructor (counted once). A conversion never lowers the count.
- **Access.** A `class-members.tsv` declaration carries the kit header's access as a label
  (`protected: igObject();`; none is public); `scripts/gen_type_headers.py` opens a section where it changes, and
  `tools/gen_odl_source.py --write-members` keeps a regenerated field handle's label.

`tools/apply_names.py --member Class::old new` (repeatable, dry run unless `--apply`) renames a member: its
`config/class-members.tsv` declaration and class bodies (not `reflected.h`, which is regenerated), its definitions
and qualified uses, its calls through an object of the class, and its compiler name in `unit-objects.json`. A call
whose receiver's class it cannot read is refused when another class has a member of that name; a member an object
macro declares is renamed in the macro.

## Session preludes

The original build compiled several source files in one MWCC process, and MWCC 3.0b52 carries state from one
file to the next: the register mask of runtime-call arguments is never cleared
([understanding shapes](engine/understanding-shapes.md#compile-session-b52)). A unit whose retail code shows
state left by an earlier file names a **session prelude** in the flags of its `config/<GAMEID>/units.tsv` row:

```
-O4,p ... -Iinclude -session-prelude config/SLUS-20836/session-preludes/<file>.cpp
```

* Every compile of the unit (`tools/check.py`, `tools/verify.py`, `tools/linkgen.py`, `make objdiff`, the sweep
  tools) goes through `tools/cc.py`, which runs one compiler process over `<prelude> <unit source>` with a
  private output folder and keeps only the unit's object; the prelude's object is discarded and links nowhere.
  A unit without the setting gets the same single-source command as before.
* A prelude is a repository-relative file under `config/<GAMEID>/session-preludes/`, MWCC only
  (`tools/unitprofiles.parse` refuses an absolute path, `..` or an EE GCC unit), and a missing file is a compile
  failure. Its comment states the compiler state it sets and why.
* The build cache keys each unit on its prelude's bytes (`tools/buildcache.unit_profile_sha`), so editing the
  prelude recomputes exactly the units that name it.
* The setting is part of the profile (`same_profile` compares flags), but not of the library profile
  `tools/progress.py` counts, and `tools/roll_profile.py` keeps it when it moves a unit.
* It models the session, not a known file: which files came first in the original session is not recorded, so a
  prelude holds the smallest code that sets the state retail shows, and a unit takes one only when its retail
  code needs that state and its own source cannot produce it.

## objdiff objects

The base object of a unit is the function's definition compiled under its unit profile, extracted
from its source file exactly as `tools/check.py` does (a registered emitted member builds its
owner). The target object holds the function's retail instructions, produced by [`tools/target_asm.py`](../tools/target_asm.py): `asm/<name>.s`
keeps every retail word as a plain `.word`, which would show each call and address pair as a
difference against the compiled object's relocations, so the target assembly emits those words
with the relocated field cleared behind a `.reloc` directive naming the same symbol the compiler
references. After relocation the target bytes are the retail bytes exactly. A unit is marked
`complete` when its function is `match` in `data/check-categories.tsv`; objdiff's
percentage is a diff measure, the matching oracle remains `tools/check.py` and `tools/linkcheck.py`.

## Private inputs

`orig/` holds one folder per version with a `.gitkeep`; everything else in it is ignored. Put a disc
image there and `make` extracts the executable, or link or copy the executable in yourself; the CI
oracle links it from its runner environment. `config.yml` records the
executable's SHA-1 so a wrong file is caught before any comparison.

`asm/`, the per-function split of the retail code, is the other private input, and a generated
one: `make check` runs `tools/split.py --ensure`, which writes it from the
executable when it is missing or stale. It is gitignored.
