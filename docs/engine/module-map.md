# game.elf's module map

_Generated by `scripts/module_map.py` -- do not hand-edit._

`config/SLUS-20836/symbols.txt` carries an address for every function but only names some; the rest are `FUN_*`. The strings a function references identify it, and vendor code is loud about itself, so contiguous runs of symbols (a run is the original translation unit -- MWCC emits a unit's functions in source order) can be attributed to a library. The regions come from `config/SLUS-20836/regions.tsv`, which `tools/check_regions.py` tests against the image.

**Why it matters:** of the 2,097 raw casts applied to a function's receiver, **1,676 (85%) are in third-party middleware**, not game code. The typing queue is the game-code remainder.

## Open questions

* **AdxMovie's origin.** It uses the game's `_GetMetaObject` macro, not Alchemy's, and the `-O3,p` build of Bec, Ndmw and `main`, so it counts with the game; who wrote it is not recorded.
* **Enbaya's classes.** The code at `0x27ede0` has vtables at `0x52d6d0` and `0x52d6f0` and no RTTI, so its classes are unnamed; that it is the codec rather than other Enbaya code is an inference.
* **Namespaces.** A class no retail string places takes its row's namespace, an inference that every class retail does place agrees with; for Attrs, Gfx and Viewer that is one class each.
* **Region names.** Audio, WindowInput, Base, SceneSearch, Collision, AdxMovie and maths describe their classes; no retail string gives them.
* **Inherited vtable slots.** 78 bodies sit in a table that only an ancestor can own, but no retail evidence says which ancestor, so they keep `FUN_` names. They belong to the parents of `igPsx2VertexArray1_1`, `igPsx2IndexArray`, `igPsx2EnvironmentMapShader`, `igPsx2VisualContext`, `igFileImagePng`, `igTransformSequence1_5` and a few others.
