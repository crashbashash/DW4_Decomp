### #1021 · confirmed

**Where:** 0x00374f1c — BLT/BLP attack-category arithmetic and FIGHTCALC

Combat attack-category signed reciprocal division was misrecovered by m2c. The signed MULT_HI(x,0x68db8bad), arithmetic right shift by 12 and addition of logical (u32)x>>31 implement truncating signed x/10000. Upstream folded the partial product/shift too early, retaining an extra correction: its old C returns 0 for x=-10000 instead of -1. The compatibility rule preserves the partial until this exact 32-bit pattern is complete and rejects different inputs, shifts, signed corrections, unsigned products and 64-bit shifts.

**Notes:** The integer proof checks endpoints of every constant-quotient interval, covering all 2^32 signed inputs by monotonicity. Synthetic MIPS decompilation and real BLTgetSleepTime output both render a single signed division after the fix. This fixes recovery semantics; it has not yet added matching combat source. Folded into #1026, the current answer for Signed reciprocal division recovery in m2c; this finding is kept for its evidence and history.

**Evidence:** tools/m2c_compat.py; testing/test_m2c_compat.py; asm/BLTgetSleepTime.s

**Where:** 0x00519310 — GAMERAM dual-switch verification/linking prerequisite

The GAMERAM compiler object emits two different ELF sections both named.rodata, each holding one 22-entry switch table.
