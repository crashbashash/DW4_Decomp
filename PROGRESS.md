**Fully linked** is the sibling number a WIP decomp is read on, and the bar above measures bytes built from recovered C/C++ over the **4,541,184-byte section** that `make link` emits and `tools/linkcheck.py` compares (`0x100000..0x554b00`, code + data). The loader also maps a zero-initialised `.bss` tail to `0x58d280`, but the link never emits it, so it is not in the denominator. The **asm bodies** are not counted: they link from `src/`, but an `asm` body is the retail instructions wrapped in a function (docs/engine/asm-body-matches.md), not recovered C, so counting it would overstate the decompilation. Elsewhere the two headlines differ (Twilight Princess: 12.07 % decompiled, 8.12 % fully linked) since a translation-unit build can only drop a unit's asm stub once the *whole* unit is decompiled. Counting **code alone**, this repo's two numbers are identical — **79.8 %** C/C++ — and that is a property of the pipeline, not a coincidence: `tools/layout.py` tiles the section per function, so `tools/linkgen.py` replaces retail one function at a time and a match is linked from source immediately. `make link` prints the accounting from the link itself — **19,242 units / 2,777,256 bytes from C/C++ (14,520 of them compiler-generated jump tables), 0 units / 0 bytes of asm bodies, 696,052 bytes from `asm/`** — and the section then compares byte-identical, so nothing decompiled is waiting to be linked.

## Readable

Matching proves the bytes; it does not make the source readable. A matched function counts as **readable** when it also passes every test below. The tests are mechanical, so this is a floor: a function can pass them all and still be hard to follow. An owner-approved assembly source counts as readable when it has a recovered name, because its approval records that no C reproduces it.

## How these numbers are produced

A function counts as decompiled when `src/<symbol>.c` or `src/<symbol>.cpp` defines it as C/C++. Every
file there was written only after `tools/verify.py` had proved its compiled bytes identical
to retail, so this is a *record* of verification rather than a re-verification: the numbers
can be computed from the repository alone, which is what lets them be published on every
push. To prove the tree again, `make check` (needs the retail ELF and the original
compiler); `make link` then rebuilds the whole section and compares it byte-for-byte.

**Fully verified** is narrower: `make check` also compares each unit's exception metadata
and symbol rules, and writes the per-unit category to `data/check-categories.tsv` (committed,
generated). This tool reads that table; when it is missing, or its row count is not the
number of decompiled units (a check run from another tree state), the figures are marked
*(categories not recorded)* and the headline falls back to the decompiled figure.

Sizes and addresses come from `config/SLUS-20836/symbols.txt`, which is committed and regenerated by
`tools/split.py`.

A function is an **asm body**, and is counted in no figure, when its definition is an MWCC `asm` function under
`#pragma optimization_level 0` — decided from the file's content, wherever the file sits
(asm bodies are not kept in the repository). A C function that contains an inline
`asm { sync }` statement is C. A **semantic name** is a recovered name that says what the
function does; the per-class boilerplate names (`*_GetMetaObject`, `*_GetVTable`,
`*_Register`, `*_InitFields`) and the vtable-slot names (`Class::vfunc_NN`) are real names
but mechanical, so they are counted in the first row and excluded from the second.
